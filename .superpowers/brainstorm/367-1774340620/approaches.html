3 Approaches to Harmonize the Palette

All three apply the same visual changes — they differ in how the CSS is structured.

A

Surgical patch RECOMMENDED

Find and fix each broken value directly in the existing CSS string. No restructuring, no new abstractions — just replace the 8 offending values.

Pros

  • Minimal change surface
  • Easy to review
  • No risk of regressions

Cons

  • Colors still hardcoded everywhere
  • Next color change requires same effort
B

CSS variable refactor

Define named tokens in :root (--color-accent, --color-hover, etc.), then replace all hardcoded values with var() references.

Pros

  • Future color changes = 1 line
  • Self-documenting palette

Cons

  • Larger diff, more to review
  • Pico CSS vars may conflict with naming
C

Extract to static CSS file

Move all styles out of the Python string into frontend/assets/style.css, served as a static file. Then apply the palette fixes.

Pros

  • Syntax highlighting, linting
  • Cleaner app.py

Cons

  • Biggest scope change
  • Requires static file serving setup
  • Out of scope for color polish
